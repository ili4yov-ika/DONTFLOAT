# Архитектура проекта DONTFLOAT

## Обзор системы

DONTFLOAT - это аудиоанализатор и корректор BPM, построенный на Qt6 с использованием паттерна Command Pattern.

## Основные компоненты

### MainWindow
- **Роль**: Центральный компонент приложения
- **Ответственность**:
  - Управление всеми UI элементами
  - Обработка загрузки аудио через QMediaPlayer
  - Сохранение настроек через QSettings
  - Координация работы всех подсистем

### WaveformView
- **Роль**: Визуализация звуковой волны
- **Ответственность**:
  - Отображение меток цикла A и B
  - Масштабирование и навигация
  - Обработка пользовательского ввода
  - Синхронизация с позицией воспроизведения

### PitchGridWidget
- **Роль**: Piano roll под основным таймлайном
- **Статус**: **Видна по умолчанию**; `Ctrl+G` или меню **Вид**; `QSettings` → `pitchGridVisible`
- **Движок**: `PianoRollEngine` — viewport, beat grid, snap, подсветка тональности в легенде
- **Ответственность**:
  - Синхронизация с WaveformView (zoom, offset, каретка, BPM, длина таймлайна)
  - Отрисовка piano roll, тактовой сетки, каретки (поверх легенды)
  - Легенда нот справа (полупрозрачная); контент таймлайна без колонки легенды
  - Плашка «Анализировать» для определения тональности после загрузки
  - Ввод: ЛКМ — seek/выбор ноты; ПКМ — pan; колёсико — вертикальный скролл; Ctrl+колёсико — zoom
  - Вертикальный скроллбар (overlay слева) с динамической прозрачностью
  - Разрез нот: `S` по каретке и режим «Разделить» (клик по ноте); режим реза — `CutMode::SnapToGrid` / `CutMode::Free`
  - Сам разрез виджет не применяет: он шлёт `noteSplitRequested(noteIndex, sample)` хосту

### PianoRollToolbar
- **Роль**: панель кнопок под пианороллом (макет `MARKDOWN/example_panel_buttons.svg` × 1.5)
- **Ответственность**:
  - Кнопка «Разделить» (checkable) и взаимоисключающая пара «Вдоль сетки» / «Свободный рез»
  - Иконки — SVG из `resources/icons/` (`trimmer`, `along_the_grid`, `free_cut`); фон и состояния — через `setStyleSheet`
  - Только UI: состояние уходит в `PitchGridWidget`, режим реза сохраняется в `QSettings`

### BPMAnalyzer
- **Роль**: Анализ BPM с использованием алгоритмов Mixxx
- **Ответственность**:
  - Детекция битов
  - Вычисление отклонений ритма
  - Интеграция с системой команд

### KeyAnalyzer
- **Роль**: Анализ тональности аудиофайлов
- **Ответственность**:
  - Поддержка мажорных и минорных тональностей
  - Интеграция с qm-dsp библиотекой

### BeatVisualizer
- **Роль**: Визуализация ударных инструментов
- **Ответственность**:
  - Цветовое кодирование по типам ударных
  - Спектрограмма для анализа частот
  - Энергетическая кривая ударных
  - Отображение силуэта ударных поверх волны

### WaveformAnalyzer
- **Роль**: Анализ волновой формы аудио
- **Ответственность**:
  - Интеграция с Mixxx библиотеками
  - Обработка аудиоданных для визуализации
  - FFT анализ
  - Фильтрация сигнала

### MarkerEngine
- **Роль**: Данные и UI меток растяжения
- **Файлы**: `include/markerengine.h`, `src/markerengine.cpp`
- **Ответственность**:
  - Структуры `MarkerData` (данные меток) и `Marker` (UI)
  - Валидация и сортировка меток
  - Правила: нулевая метка статична, минимальный сегмент 50 мс, без дубликатов
  - `MarkerUtils::detectOnsetSamples` — позиции транзиентов по огибающей;
    общий алгоритм кнопки «OD» для главного окна и плагинов

### WaveformPeaks
- **Роль**: пирамида пиков (min/max) для отрисовки волны
- **Файлы**: `include/waveformpeaks.h`, `src/waveformpeaks.cpp`
- **Ответственность**:
  - Уровни корзин (базовая — 256 сэмплов, каждая следующая вдвое грубее),
    строятся один раз на буфер (`WaveformView::peaksFor`, сброс —
    `invalidateWavePeaks` при смене аудио)
  - `range()` отдаёт пики отрезка: вблизи — точно по сэмплам, вдали — по
    корзинам; результат никогда не у́же истинного, поэтому короткие всплески
    не теряются (прежний способ прореживал по 200 проверок на пиксель)
  - Память — около 1.5% от размера аудио

### MidiExporter / MidiImporter
- **Роль**: обмен нотами пианоролла со стандартным MIDI (SMF формата 0, 480 тиков на четверть)
- **Файлы**: `include/midiexporter.h`, `src/midiexporter.cpp`,
  `include/midiimporter.h`, `src/midiimporter.cpp`
- **Ответственность**:
  - Экспорт: сэмплы → тики по BPM и частоте дискретизации, нулём файла берётся начало тактовой сетки
  - Импорт референса: разбор SMF (running status, темп мета-событием `0x51`), три режима тайминга —
    `KeepAsIs` (темп самого файла), `FitToBpm` (темп проекта), `AlignAndFitToBpm` (плюс сдвиг первой ноты
    на начало сетки)
  - `MidiImporter::detectKey` — тональность референса по взвешенной длительностями хроме
    через `KeyAnalyzer::detectKeyFromChroma`
  - `MidiImporter::analyzeKeyPerBar` — потактовая тональность референса: хрома по звучанию нот
    внутри такта, такт без нот держит тональность предыдущего, итог собирает общий с аудио
    `KeyAnalyzer::summarizeBarKeys` (доминирующая тональность, регионы, признак модуляции)
  - Референсные ноты не редактируются: `PitchGridWidget` рисует их серым позади своих нот

### Интерфейс плагинов (`plugins/ui/`)
- **Роль**: тот же интерфейс, что в главном окне, внутри DAW
  (макет `MARKDOWN/example_plugin_dontfloat.svg`)
- **Файлы**: `dontfloat_plugin_editor_shell.*` (шапка + статусбар),
  `dontfloat_plugin_theme.*` (Fusion + тёмная палитра из `src/main.cpp`),
  `dontfloat_editor_content.h` (что оболочка спрашивает у редакции),
  `dontfloat_{full,scratch,pitch}_editor.*`
- **Ответственность**:
  - Оболочка: имя редакции, кнопки `OD` / `<` / `BG` / `>` и транспорт
    ▶ ■ метроном `A` `B` ↺, один статусбар (сигнал `statusMessage`)
  - Тема: глобально — только для своего `QApplication`; при хостовом цикле Qt
    красится лишь поддерево редактора
  - Содержимое: волна + скроллбар (Scratch), поля тональностей + пианоролл +
    `PianoRollToolbar` (Pitcher), обе секции сразу (Full)
  - Мультимедиа (прослушивание, метроном) — лениво: инициализация при
    построении редактора проворачивает вложенный цикл событий хоста
  - Захват дорожки адресуется таймлайном (`TrackToolSession::writeHostFrames`):
    буфер повторяет дорожку DAW, разрыв между блоками начинает новый проход
  - Ноты одного экземпляра — референс для соседних: `SharedNoteBoard`
    (`plugins/core/dontfloat_shared_notes.*`), общая на процесс доска
    «id экземпляра → последние ноты + отметка ревизии»; редактор опрашивает её
    таймером и забирает публикацию не от себя
  - Анализ — при каждом изменении содержимого (кнопок анализа нет);
    `computeContentFingerprint` / `detectContentShift` отличают перенос клипа,
    и тогда метки, сетка, точки цикла и ноты сдвигаются без пересчёта

### TimeStretchProcessor
- **Роль**: Обработка временного растяжения аудио по меткам
- **Файлы**: `include/timestretchprocessor.h`, `src/timestretchprocessor.cpp`
- **Ответственность**:

  - Статическая lib `rubberband_single` из `thirdparty/rubberband/single/`

### TimeStretchCommand
- **Роль**: Команды undo/redo для операций растяжения по меткам
- **Файлы**: `include/timestretchcommand.h`, `src/timestretchcommand.cpp`
- **Ответственность**:
  - Сохранение состояния меток и аудио до применения
  - Отмена и повтор через QUndoStack
  - Интеграция с MainWindow и WaveformView

### TimeUtils
- **Роль**: Утилиты для работы со временем
- **Ответственность**:

  - Преобразование сэмплов в время и обратно

### MetronomeController
- **Роль**: Независимый контроллер метронома
- **Ответственность**:
  - Синхронизация с BPM трека
  - Управление сильными и слабыми долями
  - Независимая работа от воспроизведения
  - Настройка громкости долей
  - Автоматическая остановка при завершении трека

## Бандл VST3 и окно редактора в чужом хосте

Раскладка бандла задана Steinberg и у каждой системы своя:

| Система | Каталог внутри бандла | Файл модуля | Точка входа SDK |
|---|---|---|---|
| Windows | `Contents/x86_64-win` | `<имя>.vst3` (стаб) + `<имя>.vst3.impl.dll` | `dllmain.cpp` |
| Linux | `Contents/x86_64-linux` | `<имя>.so` | `linuxmain.cpp` |
| macOS | `Contents/MacOS` | `<имя>` (без расширения) + `Info.plist` | `macmain.cpp` |

Windows — единственная система со **стабом**: тонкий модуль без Qt грузит
настоящий через `LoadLibraryEx(ALTERED_SEARCH_PATH)`, чтобы Qt рядом с
плагином нашёлся раньше чужого. В остальных системах модуль один.

Ставится бандл в `lib/vst3`: каталог триплета вроде `lib/x86_64-linux-gnu`
не сканирует ни один хост.

### Встраивание окна

Хост отдаёт своё окно, и типы у систем разные: `kPlatformTypeHWND`,
`kPlatformTypeX11EmbedWindowID`, `kPlatformTypeNSView`. Под Windows окно
перевешивается вручную (`SetParent` плюс правка стиля). X11 и NSView
встраиваются одинаково и без Xlib с Objective-C: `QWindow::fromWinId`
оборачивает окно хоста, и окно редактора становится его потомком.

Под Linux есть вторая половина задачи — цикл событий. Им владеет хост, и Qt
сам себя не прокручивает: вид заявляет роль `Linux::ITimerHandler`, просит у
`IPlugFrame` интерфейс `Linux::IRunLoop` и на каждый тик (16 мс) крутит
очередь Qt. Без этого окно в DAW замирает.

## Плагин под ARA 2: откуда берётся звук, сетка и каретка

В обычном режиме плагин узнаёт дорожку только из потока блоков в `process()`:
хост подаёт вход, плагин копит его в сессии (`TrackToolSession::writeHostFrames`),
и волна собирается по мере воспроизведения. Захват идёт **только на играющем
транспорте** — на остановленном хост шлёт тишину, и она затёрла бы дорожку.

Под ARA всё иначе, и полагаться на захват там нельзя: плагин заявляет роль
`kARAPlaybackRendererRole`, то есть берёт воспроизведение на себя, и хост не
обязан класть исходные сэмплы ему на вход. Зато звук дорожки лежит в документе
целиком и доступен в любой момент.

### Звук

`AraDocumentController` читает источник целиком (`HostAudioReader`) в момент,
когда хост разрешает доступ к сэмплам, и держит копию в `AraAudioSource::monoSamples()`.
Оттуда её забирают оба редактора:

- `DontfloatScratchEditor::pullAudioFromAra()` — кладёт звук в сессию, и волна
  рисуется сразу, без проигрывания;
- `DontfloatPitchEditor::pullFromAraModel()` — берёт ноты и ту же дорожку.

Забор идёт **после** того, как разбор источника завершился (`analysisRunning()`
погас). Перенос дорожки в сессию и перерисовка волны занимают UI-поток на
сотни миллисекунд в отладочной сборке, и хост успевал не дождаться завершения
разбора — мини-DAW падал на «разбор не завершился за 30 с».

Привязку к документу раздаёт `DontfloatFullEditor::setAraBinding()` обоим
вложенным редакторам. Базовая реализация в `DontfloatEditorContent` пустая,
поэтому редактор, который её не переопределяет, ARA просто не видит.

### Какая дорожка «моя»

Прямой связи «экземпляр плагина → дорожка» в ARA нет: экземпляр узнаёт свой
аудиоисточник по клипам, которые хост назначил его ролям. Порядок поиска в
`AraDocumentController::audioSourceForInstance()` важен и выглядит так:

1. клипы роли воспроизведения (`PlaybackRenderer`);
2. клипы роли редактора (`EditorRenderer`) и её region sequences;
3. и только потом — выбор клипов в DAW (`EditorView`).

Выбор в DAW стоит последним намеренно: он общий на проект и говорит о том,
что выделил человек, а не о том, на каком клипе висит экземпляр. Пока он
стоял первым, плагин на первой дорожке показывал ноты второй, стоило
выделить её клип. Режим отказа закреплён проверкой
`testForeignSelectionDoesNotStealTheTrack`.

Тем же порядком ищется и размещение клипа — `clipForInstance()`. Обе половины
окна обязаны переводить каретку и сетку по одному и тому же клипу: у одного
источника после разреза их несколько, и «первый клип источника» у волны и
пианоролла мог оказаться разным.

### Воспроизведение

Роль `kARAPlaybackRendererRole` означает, что дорожку выдаёт плагин: хост
исходный звук на вход не подаёт. `AraPlaybackRenderer::renderBlock()` для
каждого блока проходит по назначенным клипам и подмешивает сэмплы источника с
учётом позиции клипа, смещения внутри файла и растяжения. Работает из
аудиопотока: без выделений и блокировок, готовность сэмплов — атомарный флаг.

Транспортом при этом управляет DAW (см. ниже), поэтому каретка в плагине и
каретка в проекте идут вместе.

### Тактовая сетка и каретка

Хост отдаёт темп и начало такта 1 во времени **проекта**
(`AraDocumentController::hostBeatGrid()`), а волна показывает **источник**.
Клип может стоять не в начале проекта и быть растянут, поэтому обе величины
пересчитываются через его размещение (`AraClipPlacement`):

```
время в источнике = clip.startInSource + (время в проекте − clip.startInPlayback) / clip.stretchFactor()
```

Тем же преобразованием идёт каретка: `DontfloatScratchEditor::projectSampleToSource()`
переводит позицию, которую хост даёт в `process()`, в координаты дорожки —
иначе каретка стояла бы не там, где звучит.

Позиции из `process()` приходят **не по порядку**: REAPER считает эффекты с
опережением и на фоновых потоках, поэтому за блоком на 12-й секунде идёт
блок на 11-й, а с двумя экземплярами на разных дорожках их опережение ещё и
разное. Показывать это как есть — и были рывки каретки вправо-влево.
`notifyEditorsHostPlayhead()` поэтому принимает шаг назад только большой
(перемотка, петля, старт с начала) и отбрасывает мелкий; на остановленном
транспорте фильтр сбрасывается. Плата за это — каретка идёт по самому
дальнему из посчитанных блоков, то есть может чуть опережать звук.

Каретка в окне одна на обе половины. Щелчок по волне или пианороллу и просит
DAW встать туда же (`requestHostSeek`), и сразу двигает каретку соседней
половины (`applySourcePlayhead`). Одной просьбы к хосту мало: на стоящем
транспорте DAW позицию обратно не присылает, и половины расходились.

### Транспорт

Своего транспорта у плагина под ARA нет: дорожку играет DAW. Кнопка
воспроизведения в оболочке поэтому идёт в хост —
`AraDocumentController::requestHostPlayback()` через
`ARA::HostPlaybackController` (`requestStartPlayback`, `requestStopPlayback`,
`requestSetPlaybackPosition`). Так слышно ровно то, что видно, и каретки не
расходятся.

Если хост управление транспортом не отдал, `requestHostTransport()` возвращает
false, и оболочка показывает это статусом. Своего проигрывателя она не
поднимает: в полной редакции он выдавал звук референсного канала — не тот,
что видно.

Отдал ли хост интерфейс транспорта вообще, видно в дневнике по строке
`ara.host.playback=1` (или `=0`) — она пишется один раз за сеанс. Нажать
кнопку плагина сценарием нельзя: окно рисует Qt, и ReaScript до его кнопок
не дотягивается, — поэтому проверяется отдельно доступность интерфейса
(в REAPER) и отдельно сам путь «кнопка → хост» (в мини-DAW,
`testTransportRequestsReachTheHost`).

Кнопка воспроизведения в плагине — **дублёр кнопки DAW**, а не отдельный
проигрыватель. Она и переключает транспорт хоста (играет — останавливаем,
стоит — запускаем), и показывает его состояние: транспорт пошёл из самой DAW —
кнопка здесь тоже становится «играет». Состояние приходит из `process()` через
`notifyEditorsHostTransport()`, причём только на смену: `process()` зовётся на
каждый блок, и уведомление на каждый забило бы очередь интерфейса.

Захват входных блоков (`writeHostFrames`) под ARA выключен: в роли
ARA-рендерера хост на вход ничего не кладёт, и захват только затирал бы
дорожку тишиной при каждом нажатии Play.

### Правки клипов

Рез, перенос, обрезка и растяжение приходят одинаково — в
`didUpdatePlaybackRegionProperties()`; новый клип на дорожке даёт
`didAddPlaybackRegionToRegionSequence()`. Сам звук при этом не меняется,
меняется только место на таймлайне, поэтому разбор не перезапускается.

В редакторе то же правило: звук заливается в сессию один раз, а дальше
`syncAraClipAndGrid()` перечитывает только размещение клипа и тактовую сетку.
Опрос идёт по счётчику правок `modelRevision()` — пока он не менялся, работы
нет. Перезаливать буфер на каждой правке значило бы перерисовывать волну с
нуля и терять метки.

Замечание про хост: REAPER рассылает ARA-уведомления только для правок,
зафиксированных транзакцией (`Undo_BeginBlock` / `Undo_EndBlock`). Правка в
обход транзакции до плагина не доходит вовсе.

## Система команд (Command Pattern)

### AudioCommand
- Загрузка и сохранение аудиофайлов
- Валидация форматов
- Обработка ошибок

### BeatFixCommand
- Исправление отклонений битов
- Интеграция с QUndoStack
- Поддержка отмены/повтора

### TimeStretchCommand
- Применение растяжения по меткам (Ctrl+T)
- Сохранение исходных данных для отмены
- Интеграция с QUndoStack

## Консольный режим

### Реализация
- Отдельная функция `runConsoleMode()`
- Использование `QCoreApplication` для консольного режима
- Синтетические данные для демонстрации BPM анализатора

### Командная строка
```bash
DONTFLOAT.exe -c -f <файл> [опции]
```

### Опции
- `--min-bpm`: Минимальный BPM (по умолчанию: 60)
- `--max-bpm`: Максимальный BPM (по умолчанию: 200)
- `--mixxx`: Использовать алгоритм Mixxx
- `--fast`: Быстрый анализ
- `--variable-tempo`: Предполагать переменный темп

## Система тестирования

### Структура тестов
```
tests/
├── *.cpp               # Тесты Qt Test; цели заводятся в корневом CMakeLists
├── source4test/        # Аудиофикстуры (MP3 для интеграционных тестов)
├── midi/               # MIDI и WAV, сгенерированные из них
├── reaper/             # Сценарий ReaScript для теста с настоящей DAW
├── RunQtTest.cmake     # Запуск на Windows: PATH к Qt DLL
└── README.md           # Документация тестов
```

Цели объявляются хелпером `add_qt_test()` в корневом `CMakeLists.txt`:
он подключает Qt Test, qm-dsp и Rubber Band, а на Windows заворачивает
запуск в `RunQtTest.cmake`, иначе тест не находит Qt DLL.

### Типы тестов
- **Функциональные тесты**: Проверка GUI и консольного режима
- **BPM тесты**: Тестирование анализа BPM
- **Синтетические тесты**: Тестирование с искусственными данными
- **UI тесты**: Проверка интерфейса и цветовых схем

## Растяжение по меткам: как это считается быстро

`TimeStretchProcessor::applyMarkerStretch()` режет дорожку по меткам и тянет
каждый кусок отдельно. Наивно это стоит дорого: прогон всей дорожки через
Rubber Band занимает секунды, а пересчёт нужен на **каждое** движение метки.

Держится скорость на трёх вещах.

**Сегменты независимы, и границы заякорены.** У каждого сегмента есть
`targetEndSample` — точка, куда обязан прийти его конец. Поэтому сдвиг одной
метки меняет только два соседних сегмента: дальше возмущение затухает, потому
что следующий сегмент всё равно подгоняется под свою цель.

**Кэш сегментов** (`TimeStretchProcessor::SegmentCache`). Ключ — границы,
коэффициент и режим тонкомпенсации; значение — обработанные каналы. Кэш
принадлежит вызывающему (`WaveformView`, `MainWindow`) и живёт между правками;
сбрасывается по поколению исходного аудио. В конце каждого прохода из него
выбрасывается всё, что в этом проходе не понадобилось, — размер держится на
уровне самой дорожки и не растёт от числа правок.

**Параллельный прогрев.** Коэффициенты предсказуемы заранее: цель каждой метки
известна, и собранный выход приходит именно в неё. Значит недостающие сегменты
можно посчитать сразу и одновременно (до восьми потоков), не дожидаясь друг
друга. Цикл склейки при этом не тронут — он остался эталоном и досчитывает
всё, что разошлось с предсказанием.

**Движок под задачу.** Предпросмотр считается R2 (`OptionEngineFaster`),
итоговое применение — R3 (`OptionEngineFiner`). Разницу в качестве на
растяжении в проценты не слышно, а стоит она втрое.

Итог на 60 секундах аудио со 119 метками (отладочная сборка): сдвиг метки —
397 мс вместо 18 765 мс.

Чем это удержано: `testSegmentCacheMatchesFullRender` (кэш обязан давать
побайтово тот же звук, что и счёт с нуля) и `testMarkersLandOnTheirTargets`
(метки приходят ровно в свои позиции — иначе кроссфейд на каждом стыке съедает
свои ~10 мс, ошибка копится, и к концу дорожки метки уезжают).

## Обработка аудио

### Поддерживаемые форматы
- WAV, MP3, FLAC
- Частота дискретизации: любая (нативная частота файла, без принудительного ресемплинга)
- Битность: 8/16/24/32-bit и float (конвертируется во float при загрузке)
- Каналы: Моно, Стерео

### Технические требования
- Декодирование в 32-bit float для точности
- Нормализация аудиоданных
- Асинхронная обработка для производительности
- Эффективное управление памятью

## Настройки и локализация

### QSettings
- Организация: DONTFLOAT
- Приложение: DONTFLOAT
- Версия: 0.1.0.0

### Сохраняемые параметры
- BPM трека
- Настройки метронома (громкость сильной/слабой доли)
- Режим отображения времени
- Размеры окон и элементы интерфейса
- Видимость питч-сетки (по умолчанию: видна)
- Цветовая схема
- Настройки визуализации ударных
- Выбранный язык интерфейса
- Последний открытый файл

### Локализация
- Исходный язык msgid: English (`tr()` / `.ui`)
- Поддержка русского (`ru_RU`, EN→RU) и английского (`en_US`, identity)
- Файлы в директории translations/
- Формат: ru_RU.ts, en_US.ts
